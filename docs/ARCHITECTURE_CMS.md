# Архитектура VIONEX CMS v3.6.0

## Компоненты

```text
Nginx
  └── Node.js HTTP server
        ├── публичные страницы
        ├── API заявок и событий
        ├── CMS renderer
        ├── admin API
        ├── media storage
        └── SQLite database
```

CMS встроена в существующее приложение. Это исключает отдельный PHP/MySQL-стек и сохраняет текущий запуск через `vionex-leads.service`.

## Хранилище

По умолчанию база:

```text
data/cms.sqlite
```

Таблицы:

- `cms_users` — администраторы;
- `cms_sessions` — активные сессии;
- `cms_pages` — самостоятельные страницы;
- `cms_content_items` — услуги, кейсы и статьи;
- `cms_revisions` — версии;
- `cms_media` — метаданные медиатеки;
- `cms_settings` — бренд, тема, меню, футер, публичные контакты и юридические реквизиты;
- `cms_audit_log` — журнал действий;
- `cms_meta` — версия схемы.

SQLite работает в режиме WAL. Один основной Node.js-процесс является канонической схемой запуска.

## Модель страницы

Страница хранит документ:

```json
{
  "schemaVersion": 1,
  "blocks": [
    {
      "id": "...",
      "type": "hero-premium",
      "enabled": true,
      "variant": "default",
      "data": {}
    }
  ]
}
```

Сервер принимает только известные типы блоков и очищает каждое поле согласно схеме. Неизвестные поля и блоки не сохраняются.

## Публикация

Каждая страница и материал имеют:

- `draft_json` — рабочий черновик;
- `published_json` — публичная версия;
- статус;
- дату публикации;
- историю ревизий.

Публичный рендер использует только `published_json`. Предпросмотр использует черновик и получает `noindex,nofollow`.

## Динамические материалы

Три типа:

```text
service → /services/<slug>
case    → /cases/<slug>
post    → /blog/<slug>
```

Коллекционные блоки получают опубликованные записи из базы и формируют карточки автоматически.

## Медиа

Файлы сохраняются в:

```text
data/uploads/
```

В базе хранятся оригинальное имя, безопасное системное имя, MIME, размер, title, alt и автор загрузки.

## Расширение конструктора

Новый тип блока добавляется в трёх местах:

1. схема и поля — `src/cms/block-definitions.mjs`;
2. серверный renderer — `src/cms/render.mjs`;
3. стили и, при необходимости, безопасный клиентский модуль.

После этого блок появляется в админке автоматически. Такой подход сохраняет дизайн-систему и не допускает произвольного исполняемого кода.
