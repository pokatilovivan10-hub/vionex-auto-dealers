# VIONEX CMS — инструкция администратора

## 1. Вход

Откройте:

```text
https://vionex.ru/admin
```

Введите логин и пароль, созданные серверной командой `npm run admin:create`.

Публичной регистрации нет. Не передавайте пароль в мессенджерах и не сохраняйте его в коде или `.env`.

## 2. Обзор

На главном экране отображаются:

- количество страниц;
- услуги;
- кейсы;
- статьи;
- медиафайлы;
- активные администраторы;
- последние действия.

Кнопка **«Создать резервную копию»** делает снимок `cms.sqlite` в `data/backups/`.

## 3. Страницы и конструктор

Раздел **«Страницы»** управляет главной, разделами услуг, кейсов, блога, политикой и новыми страницами.

### Безопасный порядок изменения

1. Выберите страницу.
2. Измените текст, SEO-поля или блоки.
3. Нажмите **«Сохранить черновик»**.
4. Откройте **«Предпросмотр»**.
5. Проверьте компьютер и телефон.
6. Только после проверки нажмите **«Опубликовать»**.

Черновик не попадает на публичный сайт до публикации.

### Работа с блоками

В левой части редактора находится список блоков страницы. Можно:

- добавить блок из библиотеки;
- перетащить блок мышью;
- переместить кнопками вверх/вниз;
- скрыть без удаления;
- продублировать;
- удалить;
- выбрать блок и изменить его поля справа.

Для карточек, тарифов, вопросов и галерей используются повторяемые элементы. Их также можно добавлять, копировать, удалять и сортировать.

### Первый экран

Блок **«Первый экран — динамическая планета»** управляет:

- надзаголовком;
- основным заголовком;
- акцентной строкой;
- описанием;
- двумя кнопками;
- преимуществами;
- шагами `Рынок → ЛПР → Диалог → CRM`;
- подписями около планеты;
- включением или отключением анимации.

Canvas-графика и её безопасная механика защищены шаблоном. Администратор меняет содержание, но не может случайно сломать код анимации.

## 4. Услуги, кейсы и блог

Раздел **«Услуги, кейсы, блог»** содержит три типа динамических материалов:

- услуга;
- кейс;
- статья.

Для каждого материала доступны:

- название;
- slug;
- краткое описание;
- обложка;
- теги;
- SEO title и description;
- конструктор детальной страницы;
- черновик, предпросмотр и публикация.

После публикации URL формируется автоматически:

```text
/services/<slug>
/cases/<slug>
/blog/<slug>
```

Списки на страницах `/services`, `/cases` и `/blog` могут выводить опубликованные материалы автоматически через блок **«Динамический список материалов»**.

## 5. Медиатека

Поддерживаются:

- PNG;
- JPEG;
- WebP.

Максимальный размер задаётся через `CMS_MAX_UPLOAD_MB`, по умолчанию — 8 МБ.

Для каждого изображения заполните:

- понятное название;
- `alt`, описывающий содержимое изображения.

SVG через админку запрещён. Это снижает риск внедрения исполняемого кода.

Перед удалением CMS показывает, где файл используется. Используемый файл без принудительного подтверждения не удаляется.

## 6. Меню и настройки

В разделе **«Меню и настройки»** можно изменить:

- название бренда;
- акцентную часть названия;
- тему по умолчанию;
- пункты верхнего меню;
- кнопку в шапке;
- описание футера;
- колонки и ссылки футера;
- публичный телефон, email, Telegram и ссылку на календарь;
- юридическое наименование, УНП/ИНН, регистрационный номер, адрес и email для обращений по персональным данным.

Здесь также используется схема:

```text
Черновик → Предпросмотр/проверка → Публикация
```

## 7. Заявки

Раздел **«Заявки»** показывает последние обращения, сохранённые в `data/leads.ndjson`.

Даже при временной ошибке внешней CRM локальная запись сохраняется. При подключении webhook необходимо отдельно проверить повторную доставку и создание дублей в тестовой CRM.

## 8. История и восстановление

CMS сохраняет версии при публикации и восстановлении. В истории фиксируются:

- пользователь;
- действие;
- тип объекта;
- дата и время.

Перед крупным изменением дополнительно нажмите **«Создать резервную копию»**.

## 9. Смена пароля

На сервере:

```bash
cd /var/www/bitrix2/data/www/vionex.ru
npm run admin:password
```

На Windows:

```text
CHANGE_ADMIN_PASSWORD_WINDOWS.cmd
```

После смены пароля старые сессии закрываются.

## 10. Правила безопасной публикации

1. Не публикуйте вымышленные показатели как реальные кейсы.
2. Не вставляйте токены и пароли в текстовые поля.
3. Проверяйте ссылки и телефоны.
4. Заполняйте alt у изображений.
5. Не удаляйте системные страницы без необходимости.
6. Перед изменением структуры главной сделайте резервную копию.
7. После публикации откройте страницу в обычном и мобильном режиме.
