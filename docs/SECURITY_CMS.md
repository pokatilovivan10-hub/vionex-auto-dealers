# Безопасность VIONEX CMS v3.6.0

## Реализованные меры

- публичная регистрация отключена;
- создание администратора выполняется только из терминала сервера;
- минимальная длина пароля — 12 символов;
- пароль хранится как `scrypt`-хеш с индивидуальной солью;
- сравнение хешей выполняется через constant-time проверку;
- токен сессии хранится только в `HttpOnly` cookie;
- `SameSite=Strict`, а при HTTPS-публикации также `Secure`;
- срок сессии ограничен и задаётся через `CMS_SESSION_HOURS`;
- сессия привязана к хешу IP;
- POST/PATCH/DELETE защищены CSRF-токеном;
- проверяется same-origin;
- попытки входа ограничены;
- admin HTML отдаётся с `Cache-Control: no-store`;
- все поля проходят серверную нормализацию и ограничение длины;
- произвольный HTML и JavaScript в конструкторе отсутствуют;
- SVG через медиатеку запрещён;
- PNG/JPEG/WebP проверяются по MIME и сигнатуре файла;
- имя загруженного файла не используется как путь хранения;
- директория загрузок отделена от исполняемого кода;
- предпросмотр закрыт от индексации;
- `.env` не входит в обновление;
- токены webhook/Telegram не передаются во frontend;
- публикация и восстановление записываются в аудит;
- перед публикацией создаётся резервная копия CMS.

## Эксплуатационные правила

1. Используйте уникальный пароль длиной от 16 символов.
2. Не передавайте пароль через незащищённые каналы.
3. Оставляйте Node.js на `127.0.0.1:3101`; наружу публикуется только Nginx/HTTPS.
4. Доступ к `.env`, `data/cms.sqlite` и резервным копиям должен иметь только пользователь приложения и администратор сервера.
5. Обновляйте Node.js в пределах поддерживаемой LTS-ветки после теста на резервной копии.
6. Регулярно выгружайте резервные копии за пределы сервера.
7. Не подключайте боевую CRM без тестовой воронки, минимальных прав и idempotency-контроля.

## Границы текущей версии

- встроенный лимитер входа хранится в памяти процесса; после перезапуска счётчики обнуляются;
- двухфакторная аутентификация пока не реализована;
- текущая схема рассчитана на один сервер и один экземпляр Node.js;
- автоматическое антивирусное сканирование файлов не включено, поэтому разрешены только изображения с проверкой сигнатуры;
- доступ по VPN/IP allowlist можно добавить на уровне Nginx как отдельное усиление.
