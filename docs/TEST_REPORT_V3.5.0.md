# Отчёт тестирования VIONEX LEADS v3.5.0

## Итог

Версия `3.5.0` прошла структурную, серверную, браузерную, адаптивную и миграционную проверку. Блокирующих ошибок не обнаружено.

## Автоматические серверные тесты

```text

14 pass
0 fail
```

Проверены:

- `/health` и версия `3.5.0`;
- публичные страницы и локальные ресурсы;
- CMS-маршруты;
- создание и проверка заявок;
- авторизация и CSRF;
- публикация и предпросмотр;
- сохранение настроек;
- медиатека;
- резервная копия CMS;
- безопасная миграция схемы до версии `6`;
- наличие восьми кейсов;
- миграция блока кейсов и тарифов без перезаписи пользовательского содержимого.

## Браузерный аудит

Проверены:

- тёмная тема, desktop `1440 px`;
- светлая тема, desktop `1440 px`;
- тёмная тема, mobile `390 px`.

Машинный результат: `docs/BROWSER_AUDIT_V3.5.0.json`.

## Проверка переключателя периода

Для стандартной конфигурации план «Рост» переключается:

```text
от 220 000 ₽ / мес
→
от 594 000 ₽ / квартал
```

Подпись карточки изменяется на `Оплата за квартал`, а секция получает `data-billing-period="quarterly"`. Пользовательские значения, ранее сохранённые в CMS, миграция не перезаписывает.

## Безопасность данных при обновлении

Пакет обновления не содержит и не заменяет:

- `.env`;
- `data/cms.sqlite` и WAL-файлы;
- `data/uploads/`;
- заявки и события;
- существующие резервные копии.

Перед заменой файлов установщик создаёт резервную копию приложения и отдельно сохраняет CMS-базу. При неуспешном health-check выполняется автоматический откат.

## Ограничения

- Числовые данные демонстрационных кейсов не являются подтверждёнными результатами клиентов.
- Итоговый коммерческий состав и стоимость форматов определяются после диагностики бизнеса, воронки и CRM.

## Проверка пакета обновления

Пакет установлен на изолированную копию версии `3.4.0` с существующими `.env`, CMS-базой, заявками и пользовательским файлом в `data/uploads`.

После успешной установки подтверждено:

- `/health` возвращает `version=3.5.0` и `cms=true`;
- `.env` сохранён;
- локальная заявка сохранена;
- пользовательский файл медиатеки сохранён;
- CMS-база сохранена и мигрирована;
- `/admin` возвращает HTTP 200.

Ручной `ROLLBACK.sh` восстановил `version=3.4.0`, сохранив пользовательские данные.

Отдельно смоделирован неуспешный health-check. Установщик завершился ошибкой и автоматически восстановил `version=3.4.0`, `.env`, CMS, заявку и пользовательский файл.
