# VIONEX LEADS v3.8.0

Многостраничный сайт управляемой B2B-лидогенерации с защищённой CMS и конструктором страниц.

Версия `3.8.0` выполняет полный маркетинговый и UX/UI-аудит нишевого лендинга `/services/auto-dealers`: сокращает и усиливает первый экран, выравнивает типографику и ритм, улучшает доказательные блоки, нишевую форму, мобильную адаптацию, тарифы и рабочий fallback видеокейса. Главная страница, пользовательские данные и настройки не изменяются.

## Архитектура текущего сервера

```text
Интернет → Nginx/HTTPS → Node.js 127.0.0.1:3101 → vionex-leads.service
                                         ├── публичный сайт
                                         ├── /admin
                                         ├── data/cms.sqlite
                                         ├── data/uploads/
                                         └── data/leads.ndjson
```

Для текущей установки не нужны Docker, MySQL, PostgreSQL и внешние npm-пакеты. Требуется Node.js `22.13+`; рекомендуемая ветка для сервера — Node.js 24 LTS.

## Что управляется из CMS

- страницы и их URL;
- SEO title и description;
- черновик, предпросмотр, публикация и снятие с публикации;
- порядок, видимость, копирование и удаление блоков;
- тексты, кнопки, ссылки, карточки, тарифы, FAQ, изображения и списки;
- услуги, кейсы и статьи как отдельные динамические материалы;
- меню, футер и тема по умолчанию;
- медиатека с PNG, JPEG и WebP;
- входящие заявки;
- история действий и версии материалов;
- ручные резервные копии CMS.

## Библиотека конструктора

Доступны 14 проверенных типов блоков:

1. премиальный первый экран с Canvas-планетой;
2. возможности;
3. динамический список материалов;
4. слайдер кейсов;
5. тарифы и сравнение;
6. CRM-интеграции;
7. AI-агенты;
8. FAQ;
9. CTA;
10. текстовый блок;
11. текст и изображение;
12. показатели;
13. галерея;
14. управляемый отступ.

Администратор может добавлять любое количество экземпляров этих блоков и менять их порядок. Новый *тип* блока с новой логикой или уникальной анимацией добавляет разработчик; после этого тип автоматически появляется в библиотеке конструктора. Произвольный JavaScript и необработанный HTML из админки намеренно запрещены.

## Первый локальный запуск на Windows

1. Установите Node.js 24 LTS.
2. Распакуйте архив.
3. Запустите `START_LOCAL_WINDOWS.cmd`.
4. Для создания администратора запустите `CREATE_ADMIN_WINDOWS.cmd`.
5. Откройте `http://localhost:8080/admin`.

Устанавливать зависимости через `npm install` не требуется.

Дополнительные команды:

- `CHANGE_ADMIN_PASSWORD_WINDOWS.cmd` — смена пароля;
- `BACKUP_CMS_WINDOWS.cmd` — резервная копия CMS;
- `TEST_WINDOWS.cmd` — самопроверка проекта.

## Первый запуск на сервере

После безопасного обновления создайте владельца CMS:

```bash
cd /var/www/bitrix2/data/www/vionex.ru
npm run admin:create
```

Пароль вводится интерактивно и не отображается в терминале. Минимальная длина — 12 символов. Пароль не хранится в `.env` и не записывается в открытом виде.

Админка:

```text
https://vionex.ru/admin
```

Подробная процедура обновления: `docs/DEPLOY_V3.8.0.md`.

## Данные и резервные копии

```text
data/cms.sqlite        — страницы, материалы, настройки, пользователи и история
data/cms.sqlite-wal    — служебный WAL-файл SQLite
data/uploads/          — загруженные изображения
data/backups/          — резервные копии CMS
data/leads.ndjson      — локальная резервная копия заявок
data/events.ndjson     — first-party события
```

Ручная копия:

```bash
npm run cms:backup
```

Перед каждой публикацией страницы, материала или общих настроек CMS также создаёт резервную копию базы.

## Настройки `.env`

Секреты хранятся только в `.env`. Файл не входит в архив обновления и не заменяется.

Основные параметры:

```env
SITE_MODE=demo
PUBLIC_BASE_URL=https://vionex.ru
PORT=3101
HOST=127.0.0.1
DATA_DIR=./data

CMS_DATABASE_PATH=
CMS_SESSION_HOURS=8
CMS_MAX_UPLOAD_MB=8
CMS_LOGIN_ATTEMPTS_PER_15_MIN=10
```

Для production-режима дополнительно заполняются реальные контакты, реквизиты, email для обращений по персональным данным и, при необходимости, HTTPS webhook/Telegram.

## Безопасность CMS

- публичная регистрация отсутствует;
- пароль хешируется через `scrypt` с индивидуальной солью;
- сессия хранится в `HttpOnly`, `SameSite=Strict` cookie;
- при HTTPS-публикации cookie получает флаг `Secure`;
- все изменяющие запросы защищены CSRF-токеном;
- проверяется origin запроса;
- количество попыток входа ограничено;
- сессия привязана к хешу IP;
- SVG и произвольный исполняемый код через медиатеку запрещены;
- тип и сигнатура изображения проверяются сервером;
- предпросмотр черновика закрыт от индексации;
- секреты не передаются в браузер.

## Важные ограничения

- Первый экран и блок «Наши возможности» являются текущими визуальными эталонами. Остальные блоки уже управляются через CMS и могут дорабатываться поэтапно без изменения ядра админки.
- Демонстрационные показатели и кейсы нельзя выдавать за подтверждённые результаты реальных клиентов без фактических данных и разрешения на публикацию.
- SQLite подходит для текущей схемы одного Node.js-процесса на одном сервере. При переходе к нескольким экземплярам приложения потребуется централизованная база данных.
- Изменения боевой CRM выполняются только после отдельного согласования, на тестовой воронке и с минимальными правами.
